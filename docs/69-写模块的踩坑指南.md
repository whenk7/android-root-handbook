# 69 · 写模块的踩坑指南

> 新人写模块常踩的坑。这篇帮你避开。

---

## 🕳️ KSU 模块的坑

### 坑 1：脚本里用相对路径

**错**：
```sh
./my_binary
```

**对**：
```sh
$MODDIR/bin/my_binary
```

**原因**：脚本运行时 cwd 不一定是模块目录。

### 坑 2：post-fs-data.sh 用 setprop

**错**：
```sh
setprop ro.my.prop 1
```

**对**：
```sh
resetprop -n ro.my.prop 1
```

**原因**：`setprop` 会触发 property_service，但此时 property_service 还没启动 → **死锁**。

### 坑 3：service.sh 跑前台命令

**错**：
```sh
#!/system/bin/sh
my_daemon    # 一直跑，service.sh 不退出
```

**对**：
```sh
#!/system/bin/sh
nohup my_daemon > /data/local/tmp/log 2>&1 &
```

**原因**：service.sh 不退出会拖慢开机。

### 坑 4：模块的 system/ 没生效

**可能原因**：
1. 没装 metamodule
2. 模块没启用
3. 模块的 `system/` 目录是空的
4. metamodule 自己有问题

**排查**：
```bash
# 看模块是否被挂载
adb shell su -c "mount | grep overlay"

# 看模块的 system/ 是否被挂载
adb shell "ls -la /system/etc/hosts"
```

### 坑 5：customize.sh 的 unzip 错误

**错误现象**：模块装完文件不全。

**原因**：ZIP 里有隐藏文件（`.DS_Store` 等）。

**解法**：
```bash
# 打包时排除
zip -r module.zip . -x ".*" -x "__*"
```

## 🕳️ LSP 模块的坑

### 坑 1：ClassNotFoundError

**错误**：
```
java.lang.ClassNotFoundError: com.example.Foo
```

**原因**：用了 `null` ClassLoader。

**错**：
```java
Class<?> clazz = XposedHelpers.findClass("com.example.Foo", null);
```

**对**：
```java
Class<?> clazz = XposedHelpers.findClass("com.example.Foo", lpparam.classLoader);
```

### 坑 2：NoSuchMethodError

**错误**：
```
java.lang.NoSuchMethodError: com.example.Foo.doSomething
```

**原因**：
1. 方法名写错
2. 参数类型不对
3. 方法被混淆了

**排查**：
```java
Class<?> clazz = XposedHelpers.findClass("com.example.Foo", lpparam.classLoader);
for (Method m : clazz.getDeclaredMethods()) {
    XposedBridge.log("Method: " + m);
}
```

### 坑 3：hook 没生效

**排查清单**：

```
□ LSPosed Manager 里启用了模块？
□ 目标 App 加进作用域了？
□ 强停并重启目标 App 了？
□ LSPosed 日志里有报错吗？
□ 类名/方法名拼写对吗？
□ App 是不是更新了，类名变了？
```

### 坑 4：在 hook 里抛异常导致 App 崩

**错**：
```java
new XC_MethodHook() {
    @Override
    protected void beforeHookedMethod(MethodHookParam param) {
        throw new RuntimeException("出错了");  // 目标 App 会崩
    }
};
```

**对**：
```java
new XC_MethodHook() {
    @Override
    protected void beforeHookedMethod(MethodHookParam param) {
        try {
            // 逻辑
        } catch (Throwable t) {
            XposedBridge.log(t);
        }
    }
};
```

### 坑 5：在 hook 里做耗时操作

**错**：
```java
new XC_MethodHook() {
    @Override
    protected void beforeHookedMethod(MethodHookParam param) {
        // 网络请求，2 秒
        String data = downloadFromNetwork();
    }
};
```

**后果**：每次调用这个方法都要等 2 秒，App 卡死。

**对**：耗时操作放后台线程：

```java
new XC_MethodHook() {
    @Override
    protected void beforeHookedMethod(MethodHookParam param) {
        new Thread(() -> {
            String data = downloadFromNetwork();
            // ...
        }).start();
    }
};
```

### 坑 6：模块的 Application.onCreate 没被调用

**原因**：LSP 模块在 LSPosed 进程里被加载，**模块自己的 Application 类不会跑**。

**解法**：用 `IXposedHookLoadPackage.handleLoadPackage` 作为入口。

### 坑 7：hook 静态字段没生效

**错误**：
```java
// 想改类的静态字段
XposedHelpers.setStaticObjectField(clazz, "INSTANCE", myFake);
// 但 App 拿到的是旧的
```

**原因**：静态字段在类加载时就初始化了，hook 时机太晚。

**解法**：用 `IXposedHookZygoteInit` 或在类加载前 hook：

```java
// hook ClassLoader 的 loadClass
XposedHelpers.findAndHookMethod(
    ClassLoader.class,
    "loadClass",
    String.class,
    new XC_MethodHook() {
        @Override
        protected void afterHookedMethod(MethodHookParam param) {
            if (param.args[0].equals("com.example.Foo")) {
                Class<?> clazz = (Class<?>) param.getResult();
                // 类刚加载完，现在改静态字段
                XposedHelpers.setStaticObjectField(clazz, "INSTANCE", myFake);
            }
        }
    }
);
```

## 🕳️ 通用坑

### 坑 8：模块 ID 重复

**后果**：装第二个会覆盖第一个。

**解法**：模块 ID 取个独特的，比如 `com.yourname.module`，别用 `my_module`。

### 坑 9：忘了 module.prop 用 Unix 换行

**症状**：模块装上不显示。

**解法**：用 LF 换行，不要用 Windows 的 CRLF。

```bash
# 检查
file module.prop
# 应该看到 "ASCII text"，不能看到 "with CRLF line terminators"

# 修复
dos2unix module.prop
```

### 坑 10：模块权限不对

**症状**：模块装上不工作。

**解法**：确保文件权限正确：

```bash
# 在 customize.sh 里
set_perm_recursive $MODPATH 0 0 0755 0644
```

### 坑 11：模块导致开机循环

**症状**：开机卡 logo，自动重启。

**原因**：service.sh 里有死循环或调用了不存在的命令。

**解法**：
```sh
#!/system/bin/sh
# 加这一句防止卡死
exec 2>/dev/null

# 所有命令加超时
some_command &
sleep 30 && kill $! 2>/dev/null
```

### 坑 12：调试靠"重启"

**低效**。改进：

- 改 KSU 模块：可以手动跑脚本测试
  ```bash
  adb shell su -c "cd /data/adb/modules/<MODID> && sh -x service.sh"
  ```
- 改 LSP 模块：只需强停目标 App，不用重启

## 🎯 推荐工具

### 反编译目标 App（看真实类名）

- **JADX**：https://github.com/skylot/jadx
- **MT 管理器**：手机上的反编译

### 看 App 的方法调用

- **Frida**：动态插桩
- **Xposed 自己**：写个临时模块打日志

### 看 SELinux 拦截

```bash
adb shell su -c "dmesg | grep avc"
```

## 🎯 调试心法

1. **从最简单的开始**：先打个 log，确认 hook 进入了
2. **分步验证**：每加一个功能就测一次
3. **看日志**：LSPosed 日志 + logcat + dmesg
4. **小步快跑**：改一点测一点，别一次写太多
