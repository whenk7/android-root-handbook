## 🎯 例子 1：终端模拟器（Termux）精细控制

### 需求

Termux 需要 root 跑一些命令，但你不想让它：
- 联网（防止误下载恶意脚本）
- 改系统设置（防止误改 build.prop）
- 加载内核模块（防止误刷入恶意 .ko）

### 配置

```
App Profile for com.termux:

[✓] 允许 Root（开启）

Root Profile:
  UID: 0
  GID: 0
  
  Groups（移除以下）:
    ✗ inet          # 禁止联网
    ✗ net_bt
    ✗ net_bt_admin
    ✗ sdcard_rw     # 可选：禁止写 SD 卡
  
  Capabilities（移除以下）:
    ✗ CAP_SYS_MODULE   # 禁止加载内核模块
    ✗ CAP_SYS_BOOT     # 禁止重启
    ✗ CAP_NET_ADMIN    # 禁止改网络配置（双保险）
    ✗ CAP_SYS_ADMIN    # 禁止挂载
  
  SELinux Context:
    u:r:ksu:s0        # 保持默认（或自定义更严的域）
  
  [✓] NO_NEW_PRIVS    # 防逃逸

Non-Root Profile:
  卸载模块: [默认/关]

**注**：Non-Root Profile 的"卸载模块"功能已搬到第三阶段详细讲，详见 [24-卸载模块-KSU与ZN排除列表](24-卸载模块-KSU与ZN排除列表.md)。
```

### 效果

```
Termux 跑 su → 拿到 root 的 UID/Capabilities

但：
  $ su -c "ping baidu.com"
  ping: socket: Permission denied   ← 不能联网
  
  $ su -c "insmod /sdcard/evil.ko"
  insmod: failed to load evil.ko: Operation not permitted  ← 不能加载模块
  
  $ su -c "reboot"
  reboot: Operation not permitted   ← 不能重启
```

## 🔥 例子 2：防火墙 App（AFWall+）

### 需求

AFWall+ 这种防火墙 App 需要 root 来配置 iptables，但你不想让它读你的私密文件。

### 配置

```
App Profile for dev.ukanth.ufirewall:

[✓] 允许 Root

Root Profile:
  UID: 0
  GID: 0
  
  Groups（保留网络相关，移除文件相关）:
    ✓ inet
    ✗ sdcard_rw
    ✗ sdcard_r
  
  Capabilities（只保留网络）:
    ✓ CAP_NET_ADMIN     # 配置防火墙
    ✓ CAP_NET_RAW       # raw socket
    ✗ CAP_DAC_OVERRIDE  # 不能读所有文件
    ✗ CAP_DAC_READ_SEARCH
    ✗ CAP_SYS_MODULE
    ✗ CAP_SYS_ADMIN
    ✗ 其他全部

[✓] NO_NEW_PRIVS
```

### 效果

```
AFWall 拿到 root 后：
- 能改 iptables 规则 ✓
- 不能读 /sdcard/DCIM/ 里的照片 ✗
- 不能改系统文件 ✗
```

## 🏦 例子 3：银行 App（工行）

### 需求

让工行 App 看到的是"未修改"的 /system，正常工作。

### 配置

```
App Profile for com.icbc:

[✗] 允许 Root    ← 不给它 root

Non-Root Profile:
  卸载模块: [✓] 启用   ← 让它看到干净的 /system
```

### 效果

```
工行 App：
- 没有 root 权限
- 读 /system/etc/hosts → 看到原版（不是你改的广告过滤版）
- stat 一些可疑路径 → 都返回"不存在"
- 判定"系统干净"，正常运行
```

## 🌐 例子 4：浏览器（Chrome）配合广告过滤

### 需求

让 Chrome 看到广告过滤模块改的 hosts，广告被屏蔽。但其他 App（如银行）看不到这个修改。

### 前置条件

你装了一个 KSU 广告过滤模块（改了 hosts）。

### 全局配置

```
KSU Manager → 设置:
  默认卸载模块 = ON    ← 默认所有 App 看不到模块
```

### 单个 App 配置

```
App Profile for com.icbc:
  卸载模块: ON (跟随默认)
  
App Profile for com.cmbchina:
  卸载模块: ON (跟随默认)
  
App Profile for com.android.chrome:
  卸载模块: OFF    ← Chrome 例外，能看到模块

App Profile for mark.via:
  卸载模块: OFF    ← Via 也能看到模块
```

### 效果

```
- 工行、招行 → 看到干净 hosts → 正常运行
- Chrome、Via → 看到过滤后 hosts → 广告被屏蔽
- 双赢
```

## 🎯 配置模板

### 模板 A：严格受限（不信任的 App）

```
[✓] 允许 Root
UID: 0
GID: 0
Groups: 移除 inet / sdcard_rw / net_bt 等
Capabilities: 只留 DAC_READ_SEARCH（只读）
SELinux Context: 自定义严格域
NO_NEW_PRIVS: ✓
```

**适用**：你不完全信任的 App，但需要它有 root 才能跑

### 模板 B：网络工具

```
[✓] 允许 Root
UID: 0
GID: 0
Groups: 保留 inet，移除其他
Capabilities: 只留 NET_ADMIN + NET_RAW
NO_NEW_PRIVS: ✓
```

**适用**：网络相关工具（抓包、防火墙）

### 模板 C：文件工具

```
[✓] 允许 Root
UID: 0
GID: 0
Groups: 保留 sdcard_rw，移除其他
Capabilities: 只留 DAC_OVERRIDE
NO_NEW_PRIVS: ✓
```

**适用**：文件管理器

### 模板 D：银行 App

```
[✗] 允许 Root
Non-Root Profile:
  卸载模块: ON
```

**适用**：银行/支付类 App

## 🔬 怎么验证配置

### 步骤

```
1. 配置好 App Profile
2. 强停目标 App
3. 重新打开目标 App
4. 用 App 跑些操作，看是否符合预期
```

### 验证 Termux 例子

```bash
# 在 Termux 里
$ su
# id
uid=0(root) gid=0(root) groups=...

# ping baidu.com
ping: socket: Permission denied  ← 网络被拒

# touch /system/test
touch: /system/test: Permission denied  ← 写系统被拒
```

## 🎯 经典疑问

### Q1: 我给银行 App 配了"卸载模块"，还需要 Shamiko 吗？

**需要**：
- "卸载模块"：让银行 App 看不到 /system 的修改
- Shamiko：让银行 App 看不到 Zygisk/LSPosed 的痕迹

**两者不同维度**。

### Q2: 我能给同一个 App 同时配 Root Profile 和 Non-Root Profile 吗？

**逻辑上不能**——App 要么有 root（用 Root Profile），要么没 root（用 Non-Root Profile）。

### Q3: 我把所有 App 都配成"严格受限"，是不是最安全？

**理论上是，实际上太麻烦**——很多 App 真的需要某些权限才能跑。

**建议**：默认全开 + 只对不信任的 App 收紧。
