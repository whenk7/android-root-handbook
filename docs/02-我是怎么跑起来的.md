# 02 · 我是怎么跑起来的（Android 启动流程）

> 这篇解决一个问题：**KSU、Zygisk、LSPosed、你的模块，分别在开机的哪个时刻进场**。
>
> 不知道启动流程，就看不懂 KSU 文档里的 "post-fs-data"、"late_start"、"boot-completed"，也不知道为什么有的模块要重启才生效。

---

## 🕐 完整时间线

```
按下电源键
   ↓
[Bootloader]              ← 硬件厂商代码，验证 boot 分区签名
   ↓
[Kernel 启动]              ← Linux 内核跑起来
   ↓
[init 进程] (PID=1)        ← 用户空间的第一个进程
   ↓ 读 /init.rc
   │
   ├─ 挂载分区（/system /vendor /data ...）
   │
   ├─ 【KSU 的 preinit 在这】 ← SELinux 加载前，能加载 .ko
   │
   ├─ 加载 SELinux 策略 → 进入 Enforcing 模式
   │
   ├─ 【KSU 的 post-fs-data 在这】
   │   KSU 在这阶段挂载模块（OverlayFS）
   │
   ├─ 启动 Zygote 进程
   │   │ Zygote 预加载 framework 类
   │   │
   │   │ 【Zygisk 在这注入 Zygote】
   │   │
   │   └─ Zygote 准备好，等 AMS 来 fork
   │
   ├─ 【KSU 的 late_start (service.sh) 在这】
   │
   ├─ SystemServer 启动（AMS、PMS、WMS 等系统服务）
   │
   ├─ 【KSU 的 boot-completed 在这】
   │
   └─ Launcher 显示，可以解锁了
        ↓
   用户点开微信
        ↓
   AMS 让 Zygote fork 一个进程
        ↓
   【Zygisk 模块也跟着进了新进程】
        ↓
   【LSPosed 在新进程里初始化，读启用的 LSP 模块】
        ↓
   微信进程跑 Application.onCreate()
```

---

## 🎯 几个关键时点

### 时点 1：preinit（SELinux 加载之前）

**能干什么**：
- 加载内核模块（`.ko`）
- 写 `/proc`、`/sys`
- 跑**静态链接**的二进制

**不能干什么**：
- 不能用 shell（没有 shell 可跑）
- 不能读写 Android properties（property 服务还没起）
- 不能用 `/apex`（还没挂载）

**KSU 模块怎么利用**：把配置写在模块的 `preinit/preinit.conf`，重启时由内核执行。

**限制**：整个 stage 30 秒超时，`/metadata` 分区最多用 4MB。

---

### 时点 2：post-fs-data

**特点**：
- 阻塞式（KSU 等你脚本跑完才继续）
- 10 秒超时
- Zygote 还没启动
- **此时模块还没挂载**——所以能在这里"动态改模块文件"

**典型用途**：
- 在挂载前修改模块的 `system/` 目录内容
- 根据设备状态决定要不要启用某些文件

**陷阱**：**绝对不能用 `setprop`**，会死锁整个开机流程。要改用 `resetprop -n <key> <value>`。

---

### 时点 3：late_start / service（推荐）

**特点**：
- 非阻塞
- Zygote 已启动
- 系统服务正在启动

**典型用途**：90% 的脚本应该放这里——启动 daemon、定时任务、写日志、改 props。

---

### 时点 4：boot-completed

**特点**：系统完全启动完毕（`sys.boot_completed=1`）。

**典型用途**：弹通知、拉起用户态服务、做需要系统完全就绪才能做的事。

---

## 🔄 Zygote fork 的"夹带"

理解 Zygisk 工作的关键：

```
Zygote 进程（已被 Zygisk 注入）
   │
   ├─ fork ─→ 微信进程（自带 Zygisk）
   ├─ fork ─→ B站进程（自带 Zygisk）
   └─ fork ─→ 银行进程（自带 Zygisk，除非被 DenyList 拦）
```

每个 App 进程一出生就带着 Zygisk 加载的所有模块（包括 LSPosed、ZygiskNext 等）。

**所以 LSP 模块不需要重启整机就能生效**——只要强行停止目标 App，让它重新被 fork 出来，新进程里就有你的模块了。

---

## 🧩 不同阶段改东西的"生效时机"

| 修改类型 | 生效时机 |
|---|---|
| 改模块的 `system/` 目录 | **重启**（OverlayFS 挂载发生在 post-fs-data） |
| 改模块的 `service.sh` | **重启** |
| 改模块的 `post-fs-data.sh` | **重启** |
| 改 LSP 模块代码 | **强停目标 App 即可** |
| 改 `system.prop` | **重启** |
| 改 `sepolicy.rule` | **重启** |
| 改 Zygisk DenyList | 立即生效（下次 fork 生效） |

**例外**：KSU 新版支持"hot install"，某些模块不重启就生效。但只对**不改 system 文件**的模块有效。

## 🧪 亲手验证

```bash
adb shell

# 看启动花了多久
cat /proc/uptime

# 看启动完成标志
getprop sys.boot_completed

# 看 Zygote 进程
ps -ef | grep zygote

# 看 KSU 内核态是否加载
su -c "lsmod | grep -i ksu"
# 或
su -c "cat /proc/kallsyms | grep -i ksu | head -3"
```

## 📌 常见误解

### 误解 1："改完 LSP 模块要重启手机"

**错**。改 LSP 模块只要**强停目标 App**（设置 → 应用 → 强行停止），下次启动它就会被新的 hook 接管。

### 误解 2："改完 KSU 模块重启一下 manager 就行"

**错**。KSU 模块的挂载发生在 **post-fs-data** 阶段，**只有重启才会重新挂载**。Manager 重启没用。

### 误解 3："preinit 阶段能跑 shell 脚本"

**错**。这个阶段 SELinux 还没加载，连 shell 都没有，只能跑**静态链接的二进制**。
