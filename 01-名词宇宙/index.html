    01 · 名词宇宙¶

    玩机圈最大的拦路虎不是技术，是一堆听不懂的缩写。这篇把所有名词归到 5 个层级，记层级比记名字重要。

    🗂️ 第 1 层：Root 方案（最底层）¶

    干一件事：让你拿到 root 权限。

    名词 是什么
    Magisk 老大哥，用户态 root 方案，"systemless"概念提出者
    KernelSU（KSU） 内核态 root 方案，直接在 kernel 里给 root
    SukiSU（SukiSU-Ultra） KSU 的 fork，加了 KPM、susfs 集成、非 GKI 内核支持
    KernelSU-Next KSU 的另一个社区 fork
    MKSU KSU 的 Magic Mount 分支（已停止维护）
    APatch 另一种内核 root 方案，不打 boot.img 直接 patch kernel
    KernelPatch APatch 依赖的底层内核补丁框架
    KPM KernelPatch Module，APatch/SukiSU 支持的"内核模块包"

    记忆点：Magisk 在用户态做，KSU 在内核态做，APatch 直接打内核补丁。

    🗂️ 第 2 层：Zygote 注入¶

    干一件事：把代码塞进所有 App 进程的"妈妈"Zygote 里。

    名词 是什么
    Zygote Android 所有 App 进程的"妈妈"。所有 App 都是 Zygote fork 出来的
    Zygisk Magisk 提供的能力，"在 Zygote 里跑代码"。Zygote + Magisk
    ZygiskNext 第三方做的 Zygisk 实现，让 KSU 也能用 Zygisk
    Riru 已停更的前辈，跟 Zygisk 干一样的事

    记忆点：Zygisk 是 Magisk 亲生的，KSU 用户要装 ZygiskNext 来补这个能力。

    🗂️ 第 3 层：ART Hook 框架¶

    干一件事：在 App 进程里 hook Java 方法。

    名词 是什么
    Xposed 祖师爷（rovo89），2014 年的项目，停更
    XposedBridge Xposed 的 API 库（模块开发者调用的接口）
    EdXposed Xposed 的 Riru 时代 fork，停更
    LSPosed（LSP） 当前事实标准，EdXposed 的继任者
    Vector LSPosed 的现代 fork（作者 JingMatrix）
    LSPatch LSPosed 的"无 root"版，把 hook 代码打进 APK 里
    LSPlant LSPosed 用的底层 hook 引擎（inline hook ART 方法）

    记忆点：Xposed 已死，LSPosed 是活的标准。

    🗂️ 第 4 层：隐藏与对抗¶

    干一件事：别让 App 检测到你 root 了。

    名词 是什么 工作层 现状（2026）
    susfs "SU + FS"，一个内核补丁 + 内核模块，隐藏 root 文件/挂载/进程 内核层 SukiSU 内置（CONFIG_KSU_SUSFS）；KSU 需自己集成
    selinux_hide KSU v3.3.0+ 内置 feature，伪造 SELinux 状态 内核层 KSU v3.3.0+ 内置，默认关（ksud feature set selinux_hide 1 开启）
    ZygiskNext 第三方 Zygisk 实现，v1.3.0+ 已整合 Shamiko 大部分功能 Zygisk 层 v1.3.0+ 排除列表新增 just_umount 模式
    Hide My Applist（HMA） 一个 LSP 模块，hook PackageManager 让目标 App 看不到指定应用 App 层 活跃维护
    Play Integrity Fix（PIF） 过 Google Play 完整性检测 App 层 活跃维护
    prop 隐藏 修改系统属性（ro.debuggable 等），让 App 读到"干净"值 系统级 ZN v1.3.0+ 未整合，需自己写 service.sh

    记忆点：susfs 藏文件，ZygiskNext 藏进程，HMA 藏应用列表，PIF 过 Google 检测，prop 隐藏改系统属性。多层缺一不可。

    🗂️ 第 5 层：模块¶

    干一件事：实际的功能实现。

    名词 是什么
    KSU 模块 ZIP 包，装到 /data/adb/modules/，通过 OverlayFS 改 /system 或跑脚本
    LSP 模块 APK 包，被 LSPosed 加载，在目标 App 进程里 hook Java 方法
    Metamodule KSU 特有的"元模块"——给普通模块提供挂载实现（如 meta-overlayfs）
    Zygisk 模块 被 Zygisk 加载的 .so 库（LSPosed、Shamiko 都是 Zygisk 模块）
    meta-overlayfs 官方 metamodule，用 OverlayFS 挂载
    meta-magicmount 第三方 metamodule，Magisk 风格挂载

    🧬 启动链路（把五层串起来）¶

    开机
  ↓
[第 1 层] KernelSU 在内核启动时被加载（提供 root 能力）
  ↓
[第 2 层] Zygote 启动时 ZygiskNext 注入进去
  ↓
[第 3 层] ZygiskNext 加载 LSPosed 这个 Zygisk 模块
  ↓
[第 4 层] ZygiskNext 加载 LSPosed 这个 Zygisk 模块（ZN v1.3.0+ 已整合 Shamiko）
  ↓
用户点开一个 App
  ↓
Zygote fork 出新进程，里面带着 LSPosed
  ↓
LSPosed 看目标 App 包名，加载你启用的 LSP 模块（比如 HMA）
  ↓
你的 LSP 模块在新进程里 hook Java 方法

    🎯 一句话记住每个名词¶

    名词 一句话
    Magisk 老牌 root，啥都能干但容易被检测
    KernelSU 新一代 root，在内核里做，更难检测
    SukiSU KSU 加了料的版本
    Zygote 所有 App 的妈妈
    Zygisk 在妈妈肚子里动手脚
    ZygiskNext KSU 版的 Zygisk
    LSPosed 当前活着的 Xposed
    LSPlant LSPosed 的 hook 引擎
    susfs 内核层藏 root（SukiSU 内置）
    selinux_hide KSU v3.3.0+ 内置，伪造 SELinux 状态
    ZygiskNext v1.3.0+ 藏进程 + 按 App 还原挂载
    HMA 应用列表层藏 root
    PIF 过 Google 完整性检测
    prop 隐藏 改系统属性（ro.debuggable 等）
    Metamodule
