> 现代 Android 手机的"无缝更新"是怎么实现的？为啥 OTA 之后 root 没了？

---

## 🔄 A/B 槽是啥

### 核心思想

现代 Android 手机的**很多关键分区有两份**（A 槽和 B 槽）：

```
/dev/block/by-name/
├── boot_a          ← 启动分区 A 槽
├── boot_b          ← 启动分区 B 槽
├── init_boot_a     ← 新 Android 的 init_boot（A 槽）
├── init_boot_b
├── system_a
├── system_b
├── vendor_a
├── vendor_b
├── ...
├── userdata        ← 用户数据只有一份！
└── metadata
```

### 更新流程

```
当前你跑的是 A 槽系统
   ↓
后台下载 OTA 更新
   ↓
写到 B 槽（不影响你用 A 槽的系统）
   ↓
写完后系统提示重启
   ↓
重启时 bootloader 切到 B 槽启动
   ↓
你在用 B 槽的新系统了，A 槽变成"备份"
   ↓
下次 OTA：写到 A 槽，如此往复
```

---

## 🎯 好处

- **不打断用户**：更新后台进行，你可以继续用手机
- **失败可回滚**：bootloader 检测到 B 槽启动失败会回退到 A 槽
- **更新原子性**：要么完整切换到新版本，要么保持旧版本

## 🔬 哪些分区是 A/B 的，哪些不是

### A/B 槽（双份）

```
boot_a / boot_b
init_boot_a / init_boot_b
vbmeta_a / vbmeta_b
dtbo_a / dtbo_b
vendor_boot_a / vendor_boot_b
system_a / system_b（在 super 里）
vendor_a / vendor_b（在 super 里）
product_a / product_b（在 super 里）
...
```

### 单份（不分槽）

```
userdata        ← 用户数据（总不能一份 App 装两遍）
metadata        ← OTA 状态、加密密钥
cache           ← 缓存（新版 Android 可能不要这个）
persist         ← 持久化数据（基带配置等）
```

---

## 🔍 怎么确认自己手机是不是 A/B

```bash
adb shell getprop ro.build.ab_update
# true = A/B
# false 或空 = 单槽（老手机）

# 看当前激活哪个槽
adb shell getprop ro.boot.slot_suffix
# _a 或 _b
```

## 🧬 A/B 槽的物理实现

### 两种实现方式

#### 方式 1：真物理双份

```
物理存储：
  boot 分区  = 100MB（实际两块）
  system 分区 = 3GB（实际两块）
  ...
```

**缺点**：浪费存储

#### 方式 2：动态分区（super）

```
super 分区（一整块物理存储，比如 8GB）
├── system_a    (逻辑分区)
├── system_b    (逻辑分区)
├── vendor_a    (逻辑分区)
├── vendor_b    (逻辑分区)
├── product_a
├── product_b
└── ...
```

**优点**：每个逻辑分区大小**动态调整**，按需分配。

### 看你的手机是哪种

```bash
adb shell

# 看是否有 super
ls /dev/block/by-name/ | grep super

# 看 super 里的逻辑分区
ls /dev/block/mapper/
```

## 🧬 当前激活槽的识别

### bootloader 知道

Bootloader 在启动时决定从 A 还是 B 启动。

### 系统知道

```bash
adb shell getprop ro.boot.slot_suffix
# _a 或 _b
```

### 切槽

```bash
# fastboot 模式
fastboot --set-active=a   # 切到 A 槽
fastboot --set-active=b   # 切到 B 槽
```

## 🎯 跟 root 的关系

### 关键陷阱

```
你 patch 了 init_boot_a（A 槽）
   ↓
OTA 下载新版本，写到 B 槽
   ↓
重启，bootloader 切到 B 槽
   ↓
B 槽的 init_boot_b 是原厂的
   ↓
root 没了
```

### 解法

OTA 完成后**先别重启**，在 KSU Manager 里点 **"安装到另一槽位"**：

```
OTA 完成（B 槽已写好）
   ↓
KSU Manager 提示"安装到另一槽位"
   ↓
KSU 读 B 槽的 init_boot_b（新版本的）
   ↓
对它做 patch
   ↓
把 patch 后的写回 B 槽
   ↓
重启
   ↓
bootloader 切到 B 槽
   ↓
你进入新版本 + root 还在
```

## 🎯 经典疑问

### Q1: 我 OTA 之后忘了点"安装到另一槽位"，还能补救吗？

**能，但麻烦**：

```
1. 重启 → root 没了
2. 提取当前 B 槽的 init_boot（已是新版本）
3. 用 KSU Manager 重新 patch
4. fastboot flash init_boot_b patched.img
5. 重启 → root 回来
```

### Q2: 我能直接用 fastboot 切回原槽吗？

**能**：

```
fastboot --set-active=a
fastboot reboot
```

但**新版本会丢**——你回到了旧版本。

### Q3: 我能两个槽都装 root 吗？

**能**——分别 patch 两个槽的 init_boot。

**好处**：切换槽位 root 都在。

**缺点**：每次升级都要 patch 两次。

---

## 🛠️ 实操：手动给两槽都 patch

```bash
# 假设当前激活 _a
SLOT=$(getprop ro.boot.slot_suffix)  # 输出 _a

# dump 当前槽的 init_boot（已 patch）
adb shell su -c "dd if=/dev/block/by-name/init_boot${SLOT} of=/sdcard/init_boot_a_patched.img"

# 切到 _b
adb shell su -c "dd if=/dev/block/by-name/init_boot_b of=/sdcard/init_boot_b_stock.img"

# 把 init_boot_b_stock.img 拉到电脑
# 用 KSU Manager patch
# 推回手机刷到 _b
adb push init_boot_b_patched.img /sdcard/
adb shell su -c "dd if=/sdcard/init_boot_b_patched.img of=/dev/block/by-name/init_boot_b"
```
