    05 · 挂载与覆盖（mount / OverlayFS / whiteout / mknod）¶

    这篇解决一个核心问题：KSU 怎么"改"/system 又不真的改它。

    答案就是 Linux 的挂载机制 + OverlayFS 文件系统。

    🔗 挂载（mount）是什么¶

    生活化解释¶

    你有一块移动硬盘。Windows 上插上去变成 E: 盘。

    Linux/Android 上没有"盘符"概念。你要把这个硬盘挂到某个目录上，访问那个目录就等于访问硬盘：

    物理硬盘：/dev/sdb1
挂载到：/mnt/usb
之后：ls /mnt/usb 就能看到硬盘内容

    类比：挂载就像把一栋楼的大门装到某个门牌号上——你敲那个门牌号，进的是这栋楼。

    看手机的挂载¶

    adb shell mount | grep -E " /system | /data | /vendor "

    输出示例： 

    /dev/block/dm-4 on /system type erofs (ro,seclabel,relatime)
/dev/block/sda31 on /data type f2fs (rw,seclabel,relatime)

    逐字段翻译：

    字段 含义
    /dev/block/dm-4 这是块设备文件——代表一块物理存储（system 分区）
    on /system 挂载到了 /system 这个目录
    type erofs 文件系统类型是 EROFS（只读压缩文件系统）
    (ro,...) 选项：ro = read only 只读

    📚 文件系统类型¶

    type 字段常见的几种：

    类型 用途
    ext4 老牌 Linux 文件系统，userdata 常用
    f2fs Flash-Friendly File System，为闪存优化，userdata 常用
    erofs Enhanced Read-Only FS，华为搞的只读压缩文件系统，/system 常用
    overlay OverlayFS，叠加文件系统
    tmpfs 内存文件系统，/tmp 常用
    proc /proc 虚拟文件系统
    sysfs /sys 虚拟文件系统
    fuse 用户态文件系统，/sdcard 常用

    🪟 OverlayFS：两层玻璃叠加¶

    是啥¶

    OverlayFS 是 Linux 内核自带的文件系统（2014 年进主线）。Docker 容器也用它。

    核心思想：两层目录叠加：

    下层（lowerdir）:  /system （只读，原系统）
上层（upperdir）:  /data/adb/modules/xxx/system （你的修改）
合并后（merged）:  重新挂载到 /system 给你看

    类比：两块玻璃叠起来：

    你的眼睛
   ↓
上层玻璃（可写）──┐
                 ├─ 你看到的合并视图
下层玻璃（只读）──┘

    三种操作¶

    加东西：上层有下层没有 → 合并后出现

    改东西：上层放一个同名文件 → 上层覆盖下层

    删东西：❓ 上层"什么都不放"那文件还在；上层怎么表达"我要它消失"？

    ⚪ whiteout：表达"删除"的奇怪方式¶

    OverlayFS 的规定¶

    上层目录里如果有一个字符设备文件，设备号是 0:0，它就代表"whiteout（白色覆盖）"——同名的下层文件要被视为"已删除"。

    上层放一个 字符设备、主设备号 0、次设备号 0 的文件叫 "YouTube"
       ↓
OverlayFS 看到它
       ↓
合并视图里：下层的 YouTube 不见了

    mknod 命令¶

    mknod = "make node" = 创建一个设备文件。

    mknod /path/to/YouTube c 0 0
#      │                │ │ │
#      │                │ │ └─ 次设备号 = 0
#      │                │ └─── 主设备号 = 0
#      │                └───── 'c' = 字符设备 (character device)
#      └────────────────────── 文件路径

    执行后：

    $ ls -l /path/to/YouTube
crw------- 1 root root 0, 0 Oct 19 ... /path/to/YouTube
│             │
│             └─ 0, 0 = 主设备号 0，次设备号 0
└─ 'c' 开头 = 这是个字符设备

    OverlayFS 看到 c 0 0 就知道："哦，这是 whiteout，把下层那个真的 YouTube 目录隐藏掉。"

    为啥用 c 0:0 当标记¶

    因为： - 正常文件系统里不会有人真的创建 c 0:0（没人会用主设备号 0） - 所以 OverlayFS 把这个值保留为"删除标记" - 看到它就当作"whiteout"

    这是 Linux 的"约定大于配置"——一个普通特性被借用来表达特殊含义。

    🛠️ KSU 是怎么用 OverlayFS 的¶

    挂载流程¶

    你装了一个模块到 /data/adb/modules/my_module/
模块里有 system/etc/hosts 文件
   ↓
下次开机，post-fs-data 阶段
   ↓
KSU 的 ksud 扫描 /data/adb/modules/
   ↓
对每个启用的模块，如果它有 system/ 目录：
   加入 overlay 挂载列表
   ↓
执行类似这样的 mount 命令：
   mount -t overlay overlay \
       -o lowerdir=/system,upperdir=/data/adb/modules/my_module/system \
       /system
   ↓
Zygote 启动，看到的是合并后的 /system

    完整例子：删预装 App¶

    目标：删掉 /system/app/YouTube

    做法：

    /data/adb/modules/remove_youtube/
├── module.prop
└── system/
    └── app/
        └── YouTube    ← 一个用 mknod 创建的字符设备文件（c 0:0）

    KSU 自动做法：模块的 customize.sh 里写：

    REMOVE="
/system/app/YouTube
"

    KSU 安装时看到这个变量，自动执行： 

    mknod $MODPATH/system/app/YouTube c 0 0

    效果： - 模块目录下多了个 system/app/YouTube（c 0:0） - 重启后 KSU 挂载 OverlayFS - OverlayFS 看到 c 0:0 → 把 /system/app/YouTube 隐藏 - 系统里"没有"YouTube 了（但 /system 分区上还在）

    验证¶

    adb shell
su

# 看模块里的 whiteout 文件
ls -l /data/adb/modules/remove_youtube/system/app/
# 应该看到：crw------- 1 root root 0, 0 ... YouTube

# 看 /system 现在是 overlay 挂载
mount | grep " /system "
# 应该看到 overlay 类型

    🆚 挂载方案对比¶

    不同 metamodule 选不同的"挂载方案"：

    OverlayFS（官方 meta-overlayfs）¶

    优点： - Linux 内核原生支持 - 整个目录树一次挂载 - 性能好

    缺点： - /proc/mounts 留明显痕迹（overlay on /system type overlay） - 易被检测

    Magic Mount（Magisk 风格）¶

    原理：用 bind mount 一个个文件挂过去：

    mount --bind /data/adb/modules/x/system/etc/hosts /system/etc/hosts

    优点： - 只覆盖指定文件，不动整目录 - 兼容性好

    缺点： - 每个文件都要单独挂载，性能略差 - bind mount 也留痕迹

    FUSE（用户态文件系统）¶

    原理：把文件系统逻辑放到用户态进程里跑。

    优点： - 可以做任意变换（加密、压缩、网络存储） - 极难被检测

    缺点： - 慢（用户态 <-> 内核态切换开销） - 实现复杂

    怎么选¶

    新手用官方 meta-overlayfs 就行。Magic Mount 适合 Magisk 迁移过来的模块。

    🧪 亲手实验¶

    实验 1：手动 mount 一个目录¶

    adb shell
su

# 准备一个测试目录
mkdir -p /data/local/tmp/test_lower
mkdir -p /data/local/tmp/test_upper
mkdir -p /data/local/tmp/test_merged

echo "lower 文件" > /data/local/tmp/test_lower/a.txt
echo "upper 文件" > /data/local/tmp/test_upper/b.txt

# 挂载
mount -t overlay overlay \
    -o lowerdir=/data/local/tmp/test_lower,upperdir=/data/local/tmp/test_upper \
    /data/local/tmp/test_merged

# 看合并视图
ls /data/local/tmp/test_merged/
# 应该看到：a.txt  b.txt（两层合并了）

# 卸载
umount /data/local/tmp/test_merged

    实验 2：whiteout 实验¶

    # 在上层创建 whiteout 文件
mknod /data/local/tmp/test_upper/a.txt c 0 0

# 重新挂载
mount -t overlay overlay \
    -o lowerdir=/data/local/tmp/test_lower,upperdir=/data/local/tmp/test_upper \
    /data/local/tmp/test_merged

# 看合并视图
ls /data/local/tmp/test_merged/
# 应该只看到：b.txt
# a.txt 被 whiteout 隐藏了

# 清理
umount /data/local/tmp/test_merged

    🎯 经典疑问¶

    Q1: 改完模块文件不重启行不行？¶

    不行——OverlayFS 挂载发生在开机的 post-fs-data 阶段。要重新挂载，只能重启（或 KSU 的 hot install，但只对部分模块有效）。

    Q2: OverlayFS 是 Android 的吗？¶

    不是，是 Linux 内核的。Android 只是用了 Linux 的能力。Docker 也用它。

    Q3: 直接 remount /system 为 rw 行不行？¶

    技术上行，mount -o remount,rw /system。但： - 会破坏 dm-verity 完整性校验 - OTA 会失败 - 重启后修改还在（这反而是缺点，因为你没法"恢复"）

    推荐还是用模块（systemless）。
