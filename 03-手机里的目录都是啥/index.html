    03 · 手机里的目录都是啥¶

    你天天看 /system、/data、/sdcard，但它们到底是啥？这篇把 Android 的目录结构讲清楚。

    🌳 一棵树，不是几个盘¶

    Windows 上硬盘是 C:\、D:\、E:\，每个分区有自己的盘符。

    Linux/Android 不是这样——只有一棵树，从 / 开始：

    /                        ← 根目录
├── system/              ← Android 系统文件（只读）
├── data/                ← 用户数据（你的 App、照片、设置）
├── dev/                 ← 设备文件（硬盘、键盘、传感器都是"文件"）
├── proc/                ← 进程信息（虚拟目录，不占存储）
├── sys/                 ← 内核参数（虚拟目录）
├── sdcard/              ← 内置存储（用户能看到的）
├── storage/             ← 挂载存储设备的地方
├── vendor/              ← 厂商驱动
├── product/             ← 厂商定制（MIUI、ColorOS 加的）
├── system_ext/          ← 系统扩展
├── apex/                ← Android 10+ 系统组件包
└── metadata/            ← 加密密钥、OTA 状态

    关键概念：每个目录可以"挂载"到不同的物理分区上——下一篇讲分区。

    📂 关键目录详解¶

    /system —— Android 系统本身¶

    内容： 

    /system/
├── app/          ← 系统预装 App（YouTube、Gmail...）
├── priv-app/     ← 特权系统 App（设置、电话...）
├── etc/          ← 系统配置（hosts、permissions...）
├── framework/    ← Android framework（framework.jar）
├── lib/          ← 系统动态库（.so）
├── fonts/        ← 系统字体
├── media/        ← 铃声、通知音
└── build.prop    ← 系统属性

    特点：默认只读挂载（ro），这就是为啥改 /system 要 root + OverlayFS。

    /data —— 你的所有数据¶

    内容： 

    /data/
├── data/              ← 每个 App 的"保险柜"（私有目录）
│   ├── com.tencent.mm/
│   │   ├── databases/      ← 聊天数据库
│   │   ├── shared_prefs/   ← 设置
│   │   └── files/
│   └── ...
├── adb/               ← KSU/Magisk 的"老巢"
│   ├── modules/           ← 所有模块在这
│   ├── ksu/               ← KSU 的数据
│   ├── service.d/         ← 全局开机脚本
│   └── post-fs-data.d/    ← 全局 post-fs-data 脚本
├── local/tmp/         ← 临时目录（shell 可写）
├── user/0/            ← /data/data 的符号链接
└── system/            ← 系统级数据（不是 /system 分区！）
    ├── packages.xml       ← 所有已安装 App 的登记册
    └── ...

    特点：可读写，但每个子目录有自己的 SELinux 标签和权限。

    /sdcard vs /storage/emulated/0 —— 你看到的"内部存储"¶

    它俩是同一个东西：

    /storage/emulated/0/    ← 真身
/sdcard/                ← 符号链接，指向上面

    历史原因： - 早期手机有真 SD 卡，/sdcard 就是那张卡 - 后来取消 SD 卡槽，Google 把内置存储"伪装成 SD 卡" - 再后来支持多用户，变成 /storage/emulated/<用户ID>/ - /sdcard 保留为兼容老应用的符号链接

    验证： 

    $ adb shell ls -la /sdcard
lrw-r--r-- ... /sdcard -> /storage/emulated/0
                                              ↑
                                          'l' 开头 = 符号链接

    目录内容： 

    /sdcard/
├── DCIM/              ← 相机照片
├── Pictures/          ← 图片
├── Download/          ← 下载
├── Movies/            ← 视频
├── Music/             ← 音乐
├── Documents/         ← 文档
└── Android/
    ├── data/          ← App 的"外置"数据
    ├── obb/           ← 大型游戏数据包
    └── media/

    /data/data/<包名>/ vs /sdcard/Android/data/<包名>/¶

    这俩经常搞混，但是完全不同：

    /data/data/<pkg>/ /sdcard/Android/data/<pkg>/
    物理位置 data 分区 内置存储（也走 FUSE）
    谁访问 只有这个 App（或 root） App 自己 + 文件管理器（要权限）
    存什么 数据库、私有配置、cookie 缓存、下载的资源、日志
    卸载 App 会被删 会被删
    看里面的内容 需要 root 文件管理器能看

    经典场景： - 微信聊天记录 → /data/data/com.tencent.mm/（加密 sqlite，要 root） - 微信下载的图片 → /sdcard/Android/data/com.tencent.mm/（普通文件）

    /dev/block/ —— 硬件分区的入口¶

    Linux 哲学："一切皆文件"。硬盘也是文件。

    /dev/block/
├── bootdevice/        ← 符号链接
├── by-name/           ← 按分区名（人看的）
│   ├── boot           ← boot 分区
│   ├── boot_a         ← A/B 槽的 A 槽
│   ├── boot_b
│   ├── init_boot_a    ← 新 Android 的 init_boot
│   ├── system_a
│   ├── vendor_a
│   ├── userdata       ← /data 的真身
│   └── super          ← 动态分区容器
├── dm-0               ← device mapper 虚拟设备
├── dm-4               ← /system 的真身（常是 dm）
└── sda30, sda31...    ← 物理分区

    关键：/dev/block/by-name/ 是人看的入口，里面都是符号链接，指向真正的设备文件。

    /proc 和 /sys —— 虚拟目录¶

    不是真的文件，是内核暴露出来的接口：

    /proc/
├── cpuinfo            ← CPU 信息
├── meminfo            ← 内存信息
├── mounts             ← 当前所有挂载（超重要）
├── kallsyms           ← 内核符号表（root 检测常用）
├── self/              ← 当前进程的信息
├── 1/                 ← PID=1 进程（init）
├── 1234/              ← PID=1234 的进程
└── ...

/sys/
├── kernel/            ← 内核参数
├── devices/           ← 硬件设备
└── ...

    为啥重要：App 检测 root 经常读 /proc/mounts（看挂载点）、/proc/kallsyms（看内核符号）——susfs 就是在内核里 hook 这些读取，让 App 看到假数据。

    🔍 常用命令速查¶

    adb shell

# 看目录是不是符号链接
ls -la /sdcard

# 看分区挂载在哪
mount | grep -E " /system | /data "

# 看 /dev/block 下有什么
ls /dev/block/by-name/

# 看存储多用户结构
ls /storage/emulated/

# 看 App 私有目录大小（要 root）
su -c "du -sh /data/data/com.tencent.mm/"

    🎯 经典疑问¶

    Q1: 为啥 /sdcard 不需要 root 就能写？¶

    因为它不是真分区，是 FUSE（用户态文件系统）模拟出来的"虚拟 SD 卡"。Android 系统在中间做了权限检查，但表现得像可写的。

    Q2: 我能不能把文件放到 /system 里？¶

    默认不行，因为 /system 是只读挂载。要改得用 KSU 模块（OverlayFS 覆盖）或者 mount -o remount,rw /system（不推荐，会破坏 dm-verity）。

    Q3: /data/adb/ 下的东西算"系统"还是"用户数据"？¶

    物理上在 /data 分区（用户数据），但只有 root 能访问——是 root 工具的专属空间。

    Q4: 我删了 /data/adb/modules/<某模块> 会怎样？¶

    下次重启这个模块就没了（因为模块文件不在了）。但当前还在跑，因为已经挂载/加载了。
