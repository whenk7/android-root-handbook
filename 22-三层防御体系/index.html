    22 · 三层防御体系（2026 现状）¶

    隐藏 root 不是一个工具能搞定的——得三层配合。但 2026 年的"三层"跟以前不一样了：ZygiskNext v1.3.0+ 已经吃掉了 Shamiko 的大部分功能，KSU v3.3.0+ 也内置了反检测 feature。这篇讲清楚现在每层到底是谁在干活。

    🏰 三层防御总览（2026 版）¶

                ┌────────────────────────────┐
            │      银行 App 想检测你       │
            └────────────┬───────────────┘
                         ↓
   ┌─────────────────────────────────────────┐
   │ 第 3 层：App 层                          │
   │ 工具：Hide My Applist (HMA)             │
   │ 干啥：hook PackageManager 让 App 看不到 │
   │       你装了哪些"可疑应用"               │
   │ 防线：拦截"列出所有应用"这种 API         │
   └─────────────────────────────────────────┘
                         ↓
   ┌─────────────────────────────────────────┐
   │ 第 2 层：Zygisk 层                       │
   │ 工具：ZygiskNext v1.3.0+                │
   │      （已整合 Shamiko 大部分功能）        │
   │ 干啥：                                   │
   │   ① 按 App 还原挂载（just_umount 模式）  │
   │   ② 匿名内存加载模块                    │
   │   ③ 自己的 ZN linker（更隐蔽）           │
   │ 防线：拦截"看进程里有没有可疑 .so"       │
   └─────────────────────────────────────────┘
                         ↓
   ┌─────────────────────────────────────────┐
   │ 第 1 层：内核层                          │
   │ 工具：susfs（SukiSU 内置）               │
   │      或 KSU v3.3.0+ 的 selinux_hide     │
   │ 干啥：在内核里隐藏 root 文件/挂载/进程   │
   │ 防线：拦截"读 /proc/mounts" 这种 syscall│
   └─────────────────────────────────────────┘
                         ↓
            ┌────────────────────────────┐
            │   结果：App 看到的都是干净的 │
            └────────────────────────────┘

    关键：三层缺一不可——任何一层破了都会被检测到。

    🆕 2026 年的新变化¶

    1. ZygiskNext v1.3.0+ 吃掉了 Shamiko¶

    ZygiskNext v1.3.0（2025-11-04）release note 原文：

    整合 Shamiko 的大部分功能，排除列表增加「仅还原挂载」模式，允许在对应用加载模块的同时还原挂载变更。

    意思：装了 ZygiskNext v1.3.0+，Shamiko 的 Zygisk 部分就不再需要了——ZN 自己做。

    但有两件事 ZN 没接： - prop 隐藏（改系统属性，比如 ro.debuggable、ro.secure）→ 见 25-prop隐藏 - 字体模块处理（Android 12+ 字体模块需要 FontLoader）

    2. KSU v3.3.0+ 内置了反检测 feature¶

    KSU v3.3.0 新增了 selinux_hide（feature ID=4），可以伪造 SELinux 状态给 App 看。

    开启方式： 

    adb shell su -c "ksud feature set selinux_hide 1"

    3. KSU 的"卸载模块"开关¶

    KSU Manager 里有个 "默认卸载模块" 全局开关（默认开），每个 App 的 App Profile 里还有单独的 "卸载模块" 开关。这是内核层的防御——让特定 App 看到的是"没挂模块"的干净 /system。

    详见 24-卸载模块-KSU与ZN排除列表。

    1️⃣ 内核层：susfs 与 selinux_hide¶

    干啥¶

    在内核里hook 系统调用，让目标 App 读到假数据。

    能藏什么¶

    藏什么 具体
    文件 /data/adb/ksu/、/debug_ramdisk/ 等 root 工具路径
    挂载点 /proc/mounts 里的 overlay、bind mount
    内核符号 /proc/kallsyms 里的 ksu 相关符号
    进程 su 进程
    SELinux 状态 selinux_hide 伪造 /sys/fs/selinux 访问结果

    工作方式¶

    App 调 open("/proc/mounts") → 内核拦截 → susfs 返回伪造的内容（不含 root 挂载）。

    装法¶

    • SukiSU 用户：内核已集成，直接用
    • KSU 用户：v3.3.0+ 可开 selinux_hide；susfs 需要自己集成（编译内核时开 CONFIG_KSU_SUSFS）

    详见¶

    23-susfs与内核层隐藏

    2️⃣ Zygisk 层：ZygiskNext¶

    干啥¶

    在 App 进程内抹掉 Zygisk/LSPosed 痕迹，同时按 App 还原挂载。

    能藏什么¶

    藏什么 具体
    进程内存里的 .so LSPosed 的 lspd.so、Zygisk 的 .so
    挂载点 按 App 还原 overlay 挂载（just_umount 模式）
    堆栈 不让 App 看到 Xposed 相关的类在堆栈里
    进程 cmdline 不让 App 看到 magiskd、ksud 等

    工作方式¶

    App fork 出来时，ZygiskNext 的排除列表决定： - disabled：不启用排除，正常注入 - enabled：完全排除（不注入模块） - just_umount：仅还原挂载（注入模块，但把挂载还原掉）★ v1.3.0 新增

    跟 KSU 卸载模块的关系¶

    • KSU 卸载模块：内核层，在 mount namespace 里 unmount（KSU 5.10+ 内核直接做）
    • ZN 排除列表：Zygisk 层，在进程里做（兼容老内核，或做更细粒度控制）

    两者可以共存——KSU 做粗粒度，ZN 做细粒度。但 v1.5.0+ 的 ZN 把 WebView 子进程 umount 交由 Root 方案统一管理，避免重复操作。

    详见¶

    24-卸载模块-KSU与ZN排除列表

    3️⃣ App 层：Hide My Applist (HMA)¶

    干啥¶

    hook PackageManager 的 API，让目标 App 看不到指定应用。

    能藏什么¶

    • 已安装应用列表
    • 包信息查询
    • 组件查询

    工作方式¶

    银行 App 调 PackageManager.getInstalledApplications() → HMA 拦截 → 返回过滤后的列表（不含 KSU/LSP/Magisk 等）。

    详见¶

    26-HideMyApplist藏应用

    🔗 三层是怎么配合的¶

    完整流程¶

    银行 App 启动
   ↓
【Zygisk 层】
ZygiskNext 看排除列表：
   - 如果是 just_umount → 注入但还原挂载
   - 如果是 enabled → 不注入
   - 如果是 disabled → 正常注入
   ↓
银行 App 跑起来
   ↓
【App 层】
银行 App 调 PackageManager.getInstalledApplications()
   ↓
HMA 拦截 → 返回过滤后的列表（不含 KSU/LSP）
   ↓
银行 App 觉得"没装 root 工具"
   ↓
银行 App 读 /proc/mounts
   ↓
【内核层】
susfs 拦截 → 返回伪造的 mounts（不含 overlay）
   ↓
银行 App 觉得"没挂载可疑文件系统"
   ↓
银行 App 读 /sys/fs/selinux/enforce
   ↓
selinux_hide 拦截 → 返回"1"（Enforcing）
   ↓
银行 App 觉得"手机是干净的"，正常运行

    🎯 各层"漏了"会怎样¶

    漏了哪层 后果
    内核层（没装 susfs / 没开 selinux_hide） 银行 App 读 /proc/mounts 看到 overlay → 闪退
    Zygisk 层（ZN 没配排除列表） 银行 App 读自己进程的 maps 看到 lspd.so → 闪退
    App 层（没装 HMA） 银行 App 列出应用列表看到 LSPosed Manager → 闪退
    prop 层（没改 ro.debuggable 等） 银行 App 读系统属性发现是 userdebug → 闪退

    📦 推荐配置清单（2026 版）¶

    最小配置（基础能用）¶

    1. KernelSU v3.3.0+（开 selinux_hide）或 SukiSU（已带 susfs）
2. ZygiskNext v1.3.0+（配好排除列表）
3. LSPosed

    完整配置（推荐）¶

    1. SukiSU（内核 + susfs）
2. ZygiskNext v1.3.0+（排除列表 just_umount 模式）
3. LSPosed / Vector
4. prop 隐藏（提取 Shamiko 的 service.sh 或自己写）
5. Hide My Applist
6. Play Integrity Fix

    检查清单¶

    adb shell

# 1. 内核层：susfs
su -c "cat /proc/mounts | grep ksu"
# 应该返回空（被藏了）

# 2. KSU feature 状态
su -c "ksud feature list"
# 看 selinux_hide 是不是 1

# 3. Zygisk 层：ZN 排除列表
su -c "cat /data/adb/zygisksu/denylist.txt"
# 应该有目标 App

# 4. App 层：HMA
pm list packages | grep hidemyapplist
# 应该返回包名

# 5. SELinux 状态
getenforce
# 必须是 Enforcing

    🎯 经典疑问¶

    Q1: 我能不能只用其中一层？¶

    不行——银行 App 会从多个维度检测。你只挡一层，其他层就漏了。

    Q2: 我已经三层都装了，为啥银行 App 还是闪退？¶

    可能原因： - ZN 排除列表没配对（要用 just_umount 而不是 enabled） - prop 没改（ro.debuggable=1 会被检测） - HMA 模板不全 - App 用了新检测手段

    Q3: 我需要 Play Integrity Fix 吗？¶

    看你用不用 Google 服务。如果只用国内 App，PIF 可以不用。如果要用 Google Pay、Netflix 等，PIF 必装。

    Q4: Shamiko 还要装吗？¶

    Zygisk 功能不需要（ZN v1.3.0+ 已整合）。但 prop 隐藏需要——提取 Shamiko 的 service.sh 里的 resetprop 命令，放到自己的启动脚本里跑。

    详见 25-prop隐藏。
