    72 · 模块不工作排查¶

    装了个模块没效果？这篇按概率从高到低排查。

    🔍 排查清单¶

    □ 1. 模块真的装上了吗？
□ 2. 模块启用了吗？
□ 3. 重启了吗？
□ 4. 模块的 system/ 被挂载了吗？（如果是改系统文件）
□ 5. 是 SELinux 在拦吗？
□ 6. 是模块签名不对吗？
□ 7. 是模块跟系统/KSU 版本不兼容吗？
□ 8. 是模块脚本里有错吗？

    1️⃣ 模块真的装上了吗¶

    adb shell
su

# 看模块目录
ls /data/adb/modules/

# 应该能看到模块 ID

    没有的话：模块根本没装上。看 Manager 的安装日志。

    2️⃣ 模块启用了吗¶

    adb shell
su

# 看模块目录里有没有 disable 文件
ls /data/adb/modules/<MODID>/disable

# 如果存在 → 模块被禁用了

    启用： 

    rm /data/adb/modules/<MODID>/disable
reboot

    或在 Manager 里启用。

    3️⃣ 重启了吗¶

    KSU 模块改 system/ 必须重启。

    Manager 里装完模块，必须重启才生效。

    4️⃣ 模块的 system/ 被挂载了吗¶

    前提：装了 metamodule（meta-overlayfs）。

    adb shell
su

# 看是否有 overlay 挂载
mount | grep overlay

# 看 /system 是不是 overlay
mount | grep " /system "

    如果不是 overlay： - 检查 metamodule 装了没 - 看 /data/adb/metamodule 指向哪

    5️⃣ 是 SELinux 在拦吗¶

    adb shell
su

# 看 avc 日志
dmesg | grep avc

# 看最近的
dmesg | grep avc | tail -20

    如果有 avc: denied： - 把日志贴出来 - 用 audit2allow 翻译成 sepolicy 规则 - 加到模块的 sepolicy.rule

    详见 74-SELinux拒绝怎么看。

    6️⃣ 模块的 service.sh 跑了吗¶

    adb shell
su

# 手动跑一次看错误
cd /data/adb/modules/<MODID>
sh -x service.sh

# 看输出

    常见错误： - command not found：调用了不存在的命令 - Permission denied：SELinux 拦了 - 变量没定义：脚本语法错

    7️⃣ LSP 模块特有的问题¶

    没启用模块¶

    LSPosed Manager → 模块 → 你的模块 → 启用

    没勾选作用域¶

    LSPosed Manager → 模块 → 你的模块 → 点进去 → 勾选目标 App

    没重启目标 App¶

    设置 → 应用 → 目标 App → 强行停止
然后重新打开

    看 LSPosed 日志¶

    LSPosed Manager → 日志

    看有没有你的模块的报错。

    🧪 完整排查脚本¶

    #!/bin/bash
# diagnose.sh - 诊断模块不工作

MODULE_ID=$1

if [ -z "$MODULE_ID" ]; then
    echo "用法: $0 <module_id>"
    exit 1
fi

echo "=== 诊断模块: $MODULE_ID ==="
echo ""

echo "1. 模块是否存在："
adb shell "su -c 'test -d /data/adb/modules/$MODULE_ID && echo ✓ || echo ✗'"

echo ""
echo "2. 模块是否启用："
adb shell "su -c 'test -f /data/adb/modules/$MODULE_ID/disable && echo 禁用 || echo 启用'"

echo ""
echo "3. 模块文件："
adb shell "su -c 'ls /data/adb/modules/$MODULE_ID/'"

echo ""
echo "4. module.prop："
adb shell "su -c 'cat /data/adb/modules/$MODULE_ID/module.prop'"

echo ""
echo "5. 当前 metamodule:"
adb shell "su -c 'ls -la /data/adb/metamodule'"

echo ""
echo "6. OverlayFS 挂载："
adb shell "su -c 'mount | grep overlay'"

echo ""
echo "7. 最近的 SELinux 拦截："
adb shell "su -c 'dmesg | grep avc | tail -10'"

echo ""
echo "8. ksud 日志："
adb shell "su -c 'tail -30 /data/adb/ksu/log/ksud.log'"

    🎯 经典疑问¶

    Q1: 我装的模块在 Manager 里看不到？¶

    可能： - 没有 module.prop 文件 - module.prop 里 id 不合法 - 文件权限不对（应 0644） - module.prop 用了 Windows 换行符（CRLF）

    Q2: 模块装了，重启了，但功能没生效？¶

    按上面排查清单走。

    Q3: LSP 模块 hook 不到方法？¶

    看 69-写模块的踩坑指南 的 LSP 部分。
